# REVIEW.md

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | compute_late_minutes | It treats the punch timestamp's wall clock as the shift's local date and has no attendance-day input. Host-local timestamps and overnight punches are calculated against the wrong shift start. | Run on a non-IST host, or punch at 01:00 for a 22:00-06:00 shift; the original helper can return zero late minutes. | Convert instants to IST and calculate against the attendance date, which is the previous day for the overnight window. |
| 2 | compute_work_hours | Python float round uses ties-to-even and can disagree with the contract's decimal half-up rule. | A duration whose hour value is exactly halfway at two decimals can round down to the even cent. | Use Decimal and ROUND_HALF_UP after calculating elapsed whole seconds. |
| 3 | compute_overtime | The helper subtracts an IST-aware shift end from a naive punch timestamp, which raises TypeError. It also always places shift end on the attendance date and counts any positive minutes instead of requiring 30. | Call it with the starter's naive fromtimestamp value; test an overnight punch-out or a punch-out 29 minutes after shift end. | Use UTC-aware timestamps, put an overnight shift end on the next day, and return overtime only at 30 whole minutes or more. |
| 4 | MongoClient setup and startup | The client returns naive datetimes and the app creates no indexes. The API therefore has ambiguous instants and lacks the unique keys and query indexes required for concurrency and scale. | Inspect stored or returned timestamps; inspect indexes; run duplicate requests concurrently. | Configure timezone-aware UTC reads and create idempotent unique and query-supporting indexes during startup. |
| 5 | health | It returns ok without contacting MongoDB, so it reports ready while the database is unavailable. | Stop MongoDB and call GET /health; the starter still returns 200. | Ping MongoDB and return 503 when the ping fails. |
| 6 | EmployeeIn and create_employee | The model accepts malformed employee codes, emails, dates, shift strings, lengths, and equal shift endpoints. | Submit an invalid email, 25:00 shift, equal shift times, or malformed joined_on; the starter can accept them. | Add contract validation for all create fields and reject equal shift times. |
| 7 | create_employee | Checking for an existing emp_code before insert is a race; simultaneous requests can both pass the check. | Send parallel creates for the same emp_code; without a unique index both can be stored. | Enforce a unique database index and map DuplicateKeyError to 409. |
| 8 | create_employee | created_at uses naive local datetime.now and the response returns a datetime string instead of epoch milliseconds. | Create an employee and inspect BSON timezone or the JSON type of created_at. | Store UTC BSON datetime and serialize the API value as integer epoch milliseconds. |
| 9 | list_employees | skip is page * page_size, so page 1 skips the first full page. The total also ignores the department filter, and results have no required emp_code ordering. | With page_size 2, page 1 starts at the third employee; filtered total equals the collection-wide total; order can vary. | Use (page - 1) * page_size, count the same filter, and sort by emp_code ascending. |
| 10 | list_employees | page and page_size have no lower or upper bounds. | Request page=0, page_size=0, or page_size=101; the endpoint accepts invalid pagination. | Validate page >= 1 and page_size between 1 and 100. |
| 11 | PunchInIn and punch_in | An unknown employee is not handled; indexing emp["shift_start"] raises a server error. | Punch in with an emp_code absent from employees; the starter returns 500 instead of 404. | Check for the employee and return 404 before using its shift. |
| 12 | PunchInIn | punched_at is a plain optional int and status is an unrestricted string. Seconds-looking values, floats/strings after coercion, out-of-range times, ABSENT, LEAVE, and invalid statuses are not reliably rejected. | Send a 10-digit timestamp or status ABSENT; the starter may accept it or use the wrong event time. | Use strict bounded epoch-millisecond validation and restrict punch-in status to PRESENT, WFH, or ON_DUTY. |
| 13 | punch_in | The truthiness check treats punched_at=0 as missing, and fromtimestamp uses the host timezone. It also keeps subsecond precision rather than truncating to a whole second. | Send the epoch value 0 or run on a host outside IST; the event silently becomes local now or gets a different date. | Distinguish None explicitly, convert epoch milliseconds from UTC, and truncate event instants to whole seconds. |
| 14 | punch_in and index setup | The check-then-insert duplicate test is not atomic and there is no unique (emp_code, date) constraint. | Send two identical requests in parallel; both can receive 201 and create duplicate daily records. | Insert directly under a unique natural-key index and translate the losing duplicate-key insert to 409. |
| 15 | punch_in response | The starter returns an id made from MongoDB _id, but attendance has no public id and is addressed by emp_code plus date. | Inspect a successful response; it contains an undocumented id field. | Return only the contract's attendance fields and never expose _id. |
| 16 | list_attendance | It loads every matching document into Python, sorts there, and only then slices a page. This is unbounded work and memory use on the grader's dataset. | Query a large collection and observe latency and memory growing with all matching rows. | Count the filter, sort in MongoDB, and apply skip/limit in the database using supporting indexes. |
| 17 | list_attendance | Its sort has no emp_code ascending tiebreaker, so rows with the same date have an unstable order. | Seed two employees on the same date and repeat the same page request. | Sort by date descending and emp_code ascending. |
| 18 | list_attendance | It does not reject date_from after date_to or constrain pagination/status values. | Request an inverted date range, page 0, page_size 101, or an unknown status. | Use typed date and status parameters, bounded pagination, and explicit range validation. |
| 19 | Remaining contract endpoints | Punch-out, regularization, all four analytics routes, and explain are only listed as TODOs, so the required behavior is absent. | Call any listed route; the starter returns 404. | Implement the routes, including atomic updates, correction history, MongoDB aggregation pipelines, and executionStats explain output. |

## Considered but not defects

- load_dotenv() defaults to override=False, so real environment variables already take precedence over values in a local .env file.
- The attendance-list slice starts at (page - 1) * page_size, so its page offset is correct; the employee-list offset is the one with the off-by-one error.
- The strict greater-than-10-minute test in the late helper matches the grace-period boundary for an ordinary same-day IST shift. Its timestamp and overnight handling are still defective.
- Lexical range comparisons work for valid, zero-padded YYYY-MM-DD strings; the problem is that the starter does not validate the input dates.
